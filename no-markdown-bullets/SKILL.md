# No Markdown Bullets

## 默认输出约定

输出 Markdown，或生成将粘贴、导入、转换为 GitHub、聊天、Word 的内容时，直接采用以下结构：

1. 连续叙述、解释和结论使用普通段落。
2. 有顺序、步骤、优先级或需要逐项引用的内容使用编号列表。
3. 多项并列且字段一致的内容使用表格；聊天客户端不支持表格时改用编号列表或分段。
4. 必须逐条呈现但无需编号时，使用独立段落，并保留清楚的段落边界。

不要在正文、摘要、回答、文档草稿或待发送消息中生成 Markdown 无序列表。`- item`、`* item`、`+ item`、嵌套无序列表和 `- [ ] task` 都属于此范围。把一种项目符号换成另一种并没有解决问题。

保留编号列表和 Markdown 表格。保留代码块中的原始示例、用户要求逐字引用的内容以及明确转义的字面字符；它们不是正文中的无序列表。

## 根因与边界

Markdown 的无序列表对应 HTML `<ul>`，浏览器的默认 `list-style-type` 通常是 `disc`，因此可能显示为黑色圆点。修复应发生在内容生成源头，而不是把 `-` 换成 `*`，也不是修改 GitHub 全局 CSS。

本 Skill 只管理格式结构。不改写事实、论点、术语、语气或“人味”，不执行人类化润稿，不主动修改网页样式。

校验器的检测范围有明确边界，超出部分不要假定已被覆盖：

| 输入形态 | 是否检测 |
| --- | --- |
| 行首 `-`、`*`、`+`，含任务列表、嵌套、引用块内 | 检测 |
| 闭合的 YAML `---` 或 TOML `+++` frontmatter 内部 | 跳过，不报 |
| raw HTML `<ul>`、`<li>` | 不检测 |
| 从网页或 Word 粘贴产生的 `•`、`·`、`◦` 字形 | 不检测 |
| `.mdx`、`.markdown` 文件 | 不扫描，仅 `.md` |

上述未覆盖项属于已知边界而不是缺陷。需要时由人工判断，不要因为检查器返回 `0` 就认为内容一定没有圆点来源。

## 分场景执行

根据交付目标读取 `references/scenarios.md`：

1. **GitHub**：生成合规 Markdown 源文件；不改全局 CSS，不依赖渲染后修补。
2. **聊天**：在发送前控制消息源格式；短内容优先分段，逐项内容用编号，确认客户端支持后再用表格。
3. **Word**：通过文档工具创建原生段落、编号和表格；不要把含无序列表的 Markdown 当作中间稿粘贴或转换。

如果同一份内容会流向多个场景，先生成符合本约定的共同源稿，再按目标场景转换，不为任一场景重新引入无序列表。

Word 场景可以端到端验证，因为 `.docx` 里的项目符号来自 `numPr` 定义：

```bash
python scripts/check_docx_numbering.py report.docx
```

它解析段落直接的 `w:numPr`、段落样式的 `w:numPr` 以及 `w:basedOn` 继承链，只报告解析结果为 `bullet` 的段落。这只覆盖生成或已有的文件，覆盖不到用户手工粘贴进去的内容。

## 正面生成流程

1. 先判断内容属于叙述、步骤还是同构字段，再选择段落、编号列表或表格。
2. 直接以所选结构写正文，不先写无序列表再机械替换。
3. 保留原有编号体系和表格语义，不为了规避项目符号而拆掉有效结构。
4. 交付前运行校验器；发现命中后，按语义重建该段，而不是替换列表标记字符。

在本 Skill 目录运行：

```bash
python scripts/check_markdown_bullets.py path/to/content.md
```

也可以校验整个目录或通过标准输入检查待发送文本：

```bash
python scripts/check_markdown_bullets.py path/to/docs
python scripts/check_markdown_bullets.py - < draft.md
```

退出码为 `0` 表示未发现无序列表，为 `1` 表示发现命中，为 `2` 表示输入或读取错误。校验器只读文件，不自动改写内容。

需要供 CI 消费时改用机器可读输出：

```bash
python scripts/check_markdown_bullets.py --format json path/to/docs
```

JSON 顶层包含 `tool`、`version`、`files`、`summary`，每个文件的 `findings` 项带 `line`、`code` 与 `message`。退出码语义不随格式变化。

## 可覆写规则

用户对某一次输出的明确格式指令优先于本默认约定。仅在该输出、该次指令范围内允许 Markdown 无序列表，不把例外扩展成全局偏好，也不顺带取消其他约束。

单文件、且需要在校验中记入这一例外时，使用 `--allow`。它仍打印全部命中，只把违规退出码降为 `0`；它只接受一个路径，传多个路径会以退出码 `2` 报错，因为多文件放行等于关掉检查。

文件内部需要局部例外时，用成对的行内指令，并必须写明理由：

```markdown
<!-- no-markdown-bullets: off reason="兼容旧版模板，2026Q4 移除" -->
- 这一行被豁免
<!-- no-markdown-bullets: on reason="恢复检查" -->
```

规则是：缺少 `reason` 或理由为空时不生效，区域照常检查；未闭合视为违规并报到 `off` 所在行；写在代码块内的指令无效。豁免行数会计入统计，避免例外被悄悄堆积。

## 完成判据

交付前确认：正文中没有实际无序列表；编号列表和表格仍然存在且语义未被破坏；代码块与引用示例保持原样；没有进行与格式无关的润色。自动校验与人工语义检查缺一不可。
