# 扫读代价与下游边界

本短文说明两件事：禁掉 Markdown 无序列表之后，正文可能更难一眼扫读；以及本 Skill / 脚本管不到哪些下游表现。规则细节与「不管」清单仍以 [`规则与边界.md`](规则与边界.md) 为准。

## 扫读代价

禁止面向读者的无序列表与任务列表之后，同级短项只能改成普通段落、编号列表，或放进表格。段落会拉长篇幅，编号会暗示顺序，表格在部分聊天气泡里又可能折行难看。换来的是：GitHub 预览和许多聊天气泡少一层圆点，条目更容易被逐条引用。这是观感与扫读之间的取舍，不是「可读性一定变好」。产品文档、会议纪要、参数清单等强列表体裁，若用户当次明确要求保留 bullet，可按 `SKILL.md` 例外留下普通无序列表；任务列表仍禁止。

## 管不到的下游

本 Skill 约束的是模型写出的 Markdown 语法层（行首 `-` / `*` / `+` 加空白的无序列表，以及任务列表）。它不转换 HTML 的 `<ul>` / `<li>`，不改网页或聊天客户端的 CSS，也不管粘贴进 Word 之后由 Word 自动加上的项目符号或编号。一篇在 Markdown 源稿里已经干净的正文，贴进 Word 再点一次「项目符号」，前面的约束不会跟着生效。界面上的圆点也不一定来自列表语法（例如装饰用的 `•` / `·` 是普通字符）。需要 Word 侧核验时，可另用可选脚本 `check_docx_numbering.py`；那不是本 Skill 的强制门禁。
