# 排查结论

## 结论

面向读者时，段前出现的大黑点，主要是 Markdown 无序列表被渲染出来的，不是缺字，也不是一个单独的装饰控件。

CommonMark 里，行首（可以先有少量缩进，也可以先有引用前缀）的 `-`、`*`、`+`，后面再跟空格或 Tab，会成为无序列表。只有标记、后面没有文字的空列表项也是。渲染器通常把它画成圆点，浏览器默认的 `list-style-type` 往往是 `disc`。所以换一个标记字符没有用：星号和加号同样是无序列表。

这里不承诺界面上的每一个黑点都来自 `disc`。Word 和 WPS 还受「粘贴成列表」这一步影响，粘贴选项不同，圆点可以在没有 Markdown 的情况下出现。

## 哪些字符不是列表标记

`•` 和 `·` 是普通字符。它们不会因为处在行首就变成 CommonMark 无序列表。本仓库把它们和 UL 语法分开说：约定不把它们当成要剥的列表标记，也不承诺从正文里删掉它们。

任务列表 `- [ ]`、`- [x]`、`- [X]` 仍然是无序列表再加上一个勾选框。它们会占列表结构。本仓库禁止这种写法，并且不把勾选框保留下来。

## 出现面

1. GitHub 等 Markdown 预览：源码里的无序列表会画成圆点。改网站的全局 CSS 不在本仓库范围内，也解决不了聊天和 Word。
2. AI 聊天气泡：模型若在可见正文里写出 UL，气泡会按客户端的规则画列表。有的客户端不支持表格，所以表格不能当成唯一替代。
3. Word / WPS：从聊天或 Markdown 直接粘贴，可能带上自动项目符号。取消项目符号是在 Word 里做的，不是改 Markdown 源码能单独完成的。

## 对交付的含义

源头上用段落、编号列表或表格，避免写出 UL。仓库里的 Skill 负责把这条约定交给助手。已经写出来的 UL，可以用 `scripts/strip_md_ul.py` 做可选的后处理；脚本要先在 `fixtures/` 上通过测试。Word 则靠粘贴方式和取消项目符号，步骤见 `三场景实操.md`。禁什么、留什么、任务列表为什么没有例外，见 `规则与边界.md`。

本仓库只交付这套文档、Skill 和脚本。它不修改其他仓库，也不在这里判断别的工具该怎么安装。
