# 宿主适配：Muse 与 WorkBuddy

本文说明本仓 Skill 在 Muse、WorkBuddy 上的适配结论与接入要点。它是输出约定加后处理脚本，不是宿主开关。规则细节见 [`规则与边界.md`](规则与边界.md)；安装路径见 [`install.md`](install.md)。版本与实测对齐 tip `90b40d16` / v3.2.0。

本仓约定中文名为「去黑点」；技能列表是否显示中文取决于宿主。对话里点名仍可用 id `no-markdown-bullets`。

## 1. 定位

本 Skill 的主路径是写作约定（`SKILL.md`）加仓库根目录脚本 `scripts/strip_md_ul.py`。把目录放进宿主 Skills 路径，不等于宿主已经加载，更不等于模型会在每次回复里遵守。不要把「装目录」理解成「全局硬禁圆点」。

## 2. Muse 评价摘要

| 维度 | 结论 | 说明 |
| --- | --- | --- |
| 提示词层 | 高 | 可直接读 main 版 `SKILL.md`，按约定写作；论文体试写路径已走通 |
| 原生格式层 | 中 | Muse 自定义 Skill 要无 frontmatter 的 `SKILL.md` 加旁路 `skill.yaml`，且 name 与文件夹一致；本仓是带 `name` / `description` frontmatter 的跨工具格式，原样复制不等于符合 Muse 本地规范，需要转写一层 |
| 强制执行 | 做不到 | 本质是约定加后处理，不是宿主开关；不每次明示时，容易回到默认项目符号写法 |

主仓 `SKILL.md` 仍可直接当作当次写作约定使用，不必先完成转写。

## 3. Muse 接入步骤

1. **当次直接用**：把 `skills/no-markdown-bullets/` 交给 Muse，明示按 `SKILL.md` 写作；全文落盘后，在**仓库根目录**执行 `python scripts/strip_md_ul.py --check 文件.md`（需要报告时可加 `--report`）。通过须同时满足：退出码 `0`，`stripped=0`，且 `summary.suppression_blocks == 0`。
2. **做成自定义 Skill**：转写成 Muse 目录——说明文件去掉 frontmatter，旁路补 `skill.yaml`，name 与文件夹一致。转写只改宿主包装，禁止/保留/例外的原意不得改。
3. **脚本路径**：校验仍从本仓库根调用 `scripts/strip_md_ul.py`，一次一文件；不要把脚本路径绑死在某个宿主安装副本里却找不到仓库根。
4. **只留一份安装位置**：避免多份副本互相覆盖或版本漂移。
5. **能发现 ≠ 每次遵守**：技能列表或 Discovery 能看见，只说明可点名；模型正文仍须用通过线核验。

## 4. WorkBuddy 评价摘要

| 维度 | 结论 | 说明 |
| --- | --- | --- |
| 兼容性 | 高 | 目录扫描、frontmatter、触发词、纯标准库脚本、中文路径均可；与 `doc-typeset` / `html-to-doc` 等文档流水线互补 |
| 持续生效 | 须额外一步 | 只装目录不够；要把「默认写法」抄进自定义指令 / system 区，约定才能常驻 |
| 结构性错配 | 存在 | WorkBuddy 技能是按需语义匹配加载；本约定需要贯穿全文的格式公约。点名读全文可以当次生效；上下文挤出后约束会衰减 |
| 可选加固 | `user-invocable-only` | 可设为仅用户显式调用，降低误触发 |

规则与 `strip_md_ul.py`（以及可选的 `check_docx_numbering.py`）实测能干活；它解决的是输出格式偏好，不是模型能力问题。硬强制在任意对话、子代理与产物里全局生效，仍然做不到。

## 5. WorkBuddy 三种用法

1. **自定义指令（常驻）**：把下文「默认写法」原文抄进宿主自定义指令 / system 区（与 `SKILL.md` 一致，不可改义）。这是装目录之后要持续生效的必要补充。
2. **显式点名**：对话里点名 `no-markdown-bullets`（或中文约定名「去黑点」并指向本仓 Skill），应读本仓 `SKILL.md`，并在仓库根对模型可见正文跑 `--check`。
3. **交付前校验**：不依赖模型自觉；交付前执行 `python scripts/strip_md_ul.py --check --report - body.md`，通过线同上。

复制技能目录时，若还要本地跑脚本，需能访问本仓库的 `scripts/`（以及需要时的 `docs/`）；否则 `--check` 无处落地。

## 6. 默认写法（可抄原文）

与现行 `SKILL.md` / README 用法第 2 条一致，不可改义：

生成给人看的 Markdown，或将粘贴到 GitHub、聊天、Word 的正文时：

1. 叙述、解释和结论写成普通段落。
2. 步骤、顺序和需要逐条引用的内容写成编号列表。
3. 字段对齐的对照写成表格。聊天客户端不支持表格时，改成编号列表，每条写成「字段：值」。
4. 没有顺序、又不必编号的短项，拆成独立段落。

不要先写出无序列表再替换符号。把连字符换成星号或加号，得到的仍是无序列表。

## 7. 实测背书

对齐 tip `90b40d16` / v3.2.0。曾用于约 1.9 万字论文体正文、七组格式边界构造、人工制作的 Word 项目符号样例，以及一篇强列表体裁运维手册。

以上只说明「约定 + 脚本」在上述样本上能干活。**不承诺**任意宿主或任意模型 100% 不出圆点；一次干净输出也不能证明 Skill 已在宿主里持续加载。
