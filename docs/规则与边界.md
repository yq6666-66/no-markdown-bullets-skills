# 规则与边界

本文件和 `skills/no-markdown-bullets/SKILL.md`、`scripts/strip_md_ul.py`、`fixtures/` 使用同一套口径。只描述本仓库的约定。

## 块的处理顺序

脚本按块走状态机，不是看到行首的 `-` 就删。顺序固定为：

1. Front matter 与抑制区是同一种不改写区域，内部原样保留。Front matter 只认文件第一行。YAML 以 `---` 开始，以 `---` 或 `...` 结束。TOML 以 `+++` 开始，并且只能用同样的 `+++` 结束。中间不能有空行。闭合标记必须出现在开标记之后的 200 行以内。任一条件不满足时，第一行只是分隔线，后面的 UL 照常剥。
2. 抑制指令是 `<!-- no-markdown-bullets: off reason="..." -->` 和 `<!-- no-markdown-bullets: on reason="..." -->`。`reason` 必填，双引号或单引号都可以，去掉首尾空白后必须非空。缺少 reason 的 `off` 或 `on` 都不是有效指令。抑制区不嵌套：已经开启时，再次 `off` 不增加层数；第一个有效 `on` 结束整段。未开启时的 `on` 无效。未闭合则从 `off` 保留到文件末尾，stderr 告警，退出码 `2`。已开启的围栏、HTML 原始块、front matter、缩进代码里的指令无效。行首 0 到 3 个空格，或引用前缀，不影响识别。抑制区内的空行不清掉外侧列表。
3. 围栏：三个及以上反引号，或三个及以上 `~`。记录字符和长度，CommonMark 不嵌套。容器里的围栏要先剥掉引用前缀和当前列表的内容缩进，再判断开闭。引用变浅时，开在更深引用里的围栏随引用结束，当前行重新按正文处理，这不算未闭合。真正未闭合才从开栏跳到文件末尾，stderr 告警，退出码 `2`。开栏之后的 UL 也不会剥。
4. HTML 原始块整块不改。`pre`、`script`、`style`、`textarea`、注释、处理指令、声明和 CDATA 若未闭合，跳到文件末尾并告警。`div`、`ul` 这类块级标签直到空行结束；闭合标签本身不结束这个块。因此 `</div>` 的下一行如果没有空行，仍留在原始块里。
5. 表格整块不改，包含单元格里的 `-` 和 `*`。识别方式是：一行含 `|`，下一行是 GFM 分隔行。
6. 主题分隔线在剥 UL 之前识别，原样保留。包括 `---`、`***`、`* * *`、`- - -`、`+ + +`，以及同样形状的下划线。标记不足三个的 `- -` 不是分隔线。
7. 列表紧邻续行优先于缩进代码。上一处列表项之后还没有空行时，后续缩进行按列表处理：符合嵌套或同级位置的 UL 要剥，普通续行原样保留。引用深度变化时，丢掉不属于当前引用层的列表帧：进入更深引用会结束外侧列表，回到更浅处会结束深处的列表。因此外侧列表被引用打断之后，不再落在剩余列表里的四格缩进行按缩进代码保留。只有不在这个紧邻上下文里，并且绝对缩进大于等于 4 个空格或 1 个 Tab，才保护为缩进代码。空行会中断紧邻续行。
8. 其余 UL、空列表项和任务列表，剥掉标记。

相对父项内容列再缩进 4 列及以上的行，不当作新的 UL。空行之后、绝对缩进大于等于 4、看起来像 `- item` 的行，按缩进代码保留。这两条由 `fixtures/32_deep_indent_in_list` 和 `fixtures/19_blank_interrupts` 钉死。

## 禁止

1. 行首 UL：可先有 0 到 3 个空格，或引用前缀，然后是 `-`、`*`、`+` 加空格或 Tab。
2. 空列表项：标记后面只有空白，或什么都没有。
3. 嵌套 UL，以及 `> - item` 这种引用里的 UL。引用前缀要留下。
4. 任务列表 `- [ ]`、`- [x]`、`- [X]`，星号和加号开头的同类写法也一样。剥的时候连任务框一起去掉，只留后面的文字。不宣称勾选状态还在。

## 允许

1. 有序列表 `1.` 与 `1)`，编号最多 9 位。编号标记不剥。它下面的 UL 仍然要剥。
2. Markdown 表格。
3. 用短段落代替并列项。

## 保护、不改

1. 已闭合的围栏，含 `~~~` 和围栏中的 JSON。
2. 非列表上下文的缩进代码：行首大于等于 4 个空格，或 1 个 Tab。
3. 符合上一节条件的 YAML 或 TOML front matter，以及成对闭合的抑制区。
4. 主题分隔线。
5. 行内强调。`*强调*` 不是列表，因为星号后面不是空格或 Tab。`* 这是列表` 是列表。
6. 转义的 `\-`，以及出现在行中间的连字符。

## 不管

1. HTML `<ul>` 和 `<li>` 不转换成段落。它们若构成 HTML 原始块，整块保留。
2. 宿主和网站的 CSS。本仓库不提供改 GitHub 样式的做法。
3. `•` 和 `·`。它们不是 UL 语法。

## 剥完之后

1. 用同一套规则再解析一次。结果里还有待剥 UL，退出码 `1`，这次不算完成。输入 `- - still` 会先变成 `- still`，于是失败。调用方不能把退出码 `1` 的标准输出写回文件当终稿。再跑一次可能继续变化，所以失败结果不保证幂等。
2. 退出码 `0` 的正文再跑一次，正文不变，退出码仍是 `0`。
3. 不保证语义等价。`- # 标题` 会变成标题。列表续行保持原缩进；上一行的标记被去掉之后，大于等于 4 空格的续行在重解析时可能变成缩进代码。
4. 若剥标记之后新产生未闭合围栏，同样算未完成，退出码 `1`。

## 例外

用户当次明确要求保留项目符号或 bullet 时，Skill 允许这一次输出普通 UL。例外只到这次请求，不延伸到之后的内容。

例外不适用于任务列表。本版没有任务列表的保留开关，脚本也没有 `--keep` 一类参数。用户要求保留普通 bullet 的那一次输出，不要送进脚本。

## 退出码

| 退出码 | 含义 |
| --- | --- |
| 0 | 处理完成，结果里没有残留 UL。源文件里原来有 UL 时，只要被剥干净，仍然是 0 |
| 2 | 有跳过。当前指未闭合围栏、未闭合抑制区，或未闭合的 `pre` / `script` / `style` / `textarea` 等 HTML 原始块。结果里没有残留 UL |
| 1 | 失败。包括剥后仍有 UL、剥后新产生跳过区、文件打不开、编码不是 UTF-8、参数错误 |

`--check` 不把正文写到 stdout，退出码与默认改写相同。`--dry-run` 把正文写到 stdout，并在 stderr 标明没有修改源文件。两种模式都不会写回源文件；默认模式同样只写 stdout。

`--report PATH` 把 JSON 写到文件。`--report -` 把 JSON 写到 stderr，并且不再混入上面的人类可读诊断。JSON 里有 `exit_code`、`findings` 和 `regions`。`findings[].exit_class` 的取值是 `0`、`2`、`1`，进程退出码取其中更严重的一档：有 `1` 就是 `1`，否则有 `2` 就是 `2`，否则是 `0`。`stripped` 的 `exit_class` 是 `0`，它只说明剥过，不单独把退出码变成失败。JSON 不包含改写后的正文，正文仍然只在 stdout。

稳定诊断行如下。

| 诊断 | 含义 |
| --- | --- |
| `info: stripped=<N> lines=<行号或 ->` | 从输入里剥掉的 UL 行。行号从 1 计，没有则为 `-` |
| `warning: unclosed fence at line <N>; skipping through EOF` | 未闭合围栏 |
| `warning: unclosed html block at line <N>; skipping through EOF` | 未闭合的 HTML 原始块 |
| `warning: unclosed suppression at line <N>; keeping through EOF` | 未闭合抑制区，从该行保留到文件末尾 |
| `error: residual unordered list at output line <N>` | 输出里仍有 UL |
| `error: strip created a skipped region; result is unfinished` | 剥完后新产生跳过区 |
| `info: dry-run source-not-modified` | 仅 `--dry-run` |

要确认源文件本来就没有待剥 UL，不能只看退出码 `0`，还要看到 `stripped=0`。

## 与脚本的关系

Skill 管模型默认怎么写。脚本是可选后处理。脚本的行为以本文件和 `fixtures/` 为准：每个目录有 `input.md`、`expected.md` 和 `meta.json`，其中 `skip_reason` 说明保护或失败的原因。验收命令是仓库根目录的 `python -m unittest discover -s tests -v`。
