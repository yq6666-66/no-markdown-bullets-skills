## 强制声明

本文件是输出约定，不是宿主里的硬开关。宿主可以不加载它，模型也可以在某次回答里重新写出无序列表。这里不承诺消掉界面上的一切圆点。圆点不一定来自 `list-style: disc`，Word 还受粘贴方式影响。

## 验证

1. 按上表放入目录后，新开一段对话，请宿主列出当前能发现的 Skill。名单里要出现 `no-markdown-bullets`。
2. 用固定提示词显式要求按本约定作答。提示词写在 `docs/三场景实操.md`。
3. 把模型的可见正文存成文件，在仓库根目录执行 `python scripts/strip_md_ul.py --check --report - 该文件`。通过要同时满足：退出码 `0`，报告里 `stripped=0`，并且 `summary.suppression_blocks` 为 `0`。不想看报告时，正文里也不能出现 `no-markdown-bullets:`。
4. 这条只核对 Skill 和宿主验证时的模型正文。人工源文件仍可使用抑制区。脚本默认仍保留抑制区内的原文，不因为这条通过线改掉。
5. 通过线按解析后的 UL 节点计数，不是按截图里有没有黑点。围栏、front matter、表格和缩进代码里的标记不计入。模型用抑制注释把 UL 藏起来时，即使 `stripped=0` 也不算通过。
6. 一次没有黑点的回答，不能反过来证明第 1 步已经成功。

本仓库交付时没有附带某次宿主发现或调用的实测记录。

## 默认写法

生成给人看的 Markdown，或将粘贴到 GitHub、聊天、Word 的正文时：

1. 叙述、解释和结论写成普通段落。
2. 步骤、顺序和需要逐条引用的内容写成编号列表。
3. 字段对齐的对照写成表格。聊天客户端不支持表格时，改成编号列表，每条写成「字段：值」。
4. 没有顺序、又不必编号的短项，拆成独立段落。

不要先写出无序列表再替换符号。把连字符换成星号或加号，得到的仍是无序列表。

## 禁止

行首可以先有不超过 3 个空格，也可以先有引用前缀。在这之后如果出现 `-`、`*` 或 `+`，再跟上空格或 Tab，就是无序列表。只有标记、后面没有文字的空列表项也禁止。嵌套的无序列表、引用里的无序列表，同样禁止。

任务列表禁止，而且不能靠「用户要求保留 bullet」留下来。下面三种都要改掉：

```markdown
- [ ] 待办
- [x] 已完成
- [X] 已完成
```

改成普通句子或编号列表，去掉勾选框。不要说勾选状态已被保留。

## 保留

1. 有序列表，例如 `1.` 和 `2)`。
2. Markdown 表格。
3. 围栏代码（三个反引号或 `~~~`）、缩进代码，以及围栏里的 JSON。
4. 文件开头且成对闭合的 YAML front matter，以及同样位置、中间没有空行、200 行窗口内闭合的 TOML front matter。闭合条件以 `docs/规则与边界.md` 为准。
5. 主题分隔线，例如 `---`、`***`、`* * *`、`- - -`，以及同样形状的下划线。整行只有 `+` 与空白、且加号不少于三个的行（例如 `+ + +`）不再当作分隔线保留，围栏外会剥成空行。
6. 行内强调，例如一句中间的 `*强调*`。和列表的差别是：列表标记后面有空格或 Tab。
7. `•` 和 `·` 是普通字符，不是 CommonMark 的列表标记。本约定不把它们当成 UL，也不承诺把它们从正文里删掉。

## 不管

1. HTML 的 `<ul>` 和 `<li>` 不在本约定的改写范围。需要时人工改结构。
2. 不改 GitHub、聊天客户端或 Word 的样式。
3. 不做文风润色，不改事实，也不把正文改得更像人写的。

## 例外

用户在当次请求里明确要求保留项目符号或 bullet 时，这一次普通无序列表可以按用户的要求输出。例外到这次请求为止，不变成以后的默认。

例外不覆盖任务列表。即使用户同时要求保留 bullet 和勾选框，任务列表仍然改成纯文本，并且不要宣称勾选还在。

脚本 `scripts/strip_md_ul.py` 没有保留 bullet 的开关。用户当次要求保留普通 UL 时，不要对那一次输出运行脚本。

人工编辑源文件时，可以用抑制注释把一段标成不改写。模型生成给人看的正文时，不要写出这种注释来藏无序列表。抑制区的语法、reason 要求和未闭合时的退出码 `2` 写在 `docs/规则与边界.md`。

## 和脚本的关系

Skill 约束的是生成时的写法。脚本是可选的后处理，用来剥掉已经写出来的 UL 标记。块的处理顺序、空行和缩进代码的分界，以 `docs/规则与边界.md` 和 `fixtures/` 为准。脚本退出码 `1` 表示没做完，那段标准输出不能当作成功结果。
