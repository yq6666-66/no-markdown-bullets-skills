# 去黑点 · Web 版

把 AI 味的圆点列表从 Markdown 里干净剔除的在线工具。粘贴文本，立刻看到清理结果、前后对比和逐行诊断。

## 在线体验

https://dedot.app.workbuddy.host/?sharecode=6WUJJLETYU

无需注册，打开即用。全部计算在浏览器本地完成，内容不上传服务器。

## 三个视图

**清理结果**是直接可复制的干净文本，也可以一键下载成 `.md` 文件。

**前后对比**左右并排渲染同一段内容，左侧的红点就是命中处，右侧已全部清空。这一屏就是产品价值本身。

**诊断**逐行列出第几行属于圆点列表、任务勾选框还是引用内列表，方便人工复核而不是盲信工具。

## 难的不是删，是删得准

下面这些地方出现的减号、星号、加号，一个都不会被删：围栏代码块与缩进代码块里的符号、表格单元格里的短线、自带顺序语义的有序列表、TOML 与 YAML 元数据块、被抑制区标记包裹的段落。这是按块推进的状态机，不是正则替换。

## 规则保真

本项目的清理引擎是本仓库 `scripts/strip_md_ul.py` 的 JavaScript 移植，并用两种方式验证过：

| 验证方式 | 结果 |
| --- | --- |
| 本仓库官方 fixtures 逐字节比对 | 67 / 67 一致 |
| 随机差分测试（Python 与 JS 同输入比对） | 400 次，零差异 |
| 页面行为冒烟测试 | 22 / 22 通过 |

这意味着浏览器里的行为和命令行版本是同一套规则，不是看起来差不多。

## 本地开发

`index.src.html` 是页面模板，`qudiao.js` 是清理引擎，`build.js` 负责把引擎内联生成可发布的 `index.html`。

改完源码必须跑一次构建再发布，否则线上不会更新：

```
node build.js
```

之所以要内联，是因为部分发布网关会对每个请求校验访问码，外部 `.js` 子资源存在被拦截的风险。内联后成品零外部请求，可以直接转发、离线打开。

构建输出示例：

```
构建完成
  模板     : index.src.html 33.4 KB
  引擎     : qudiao.js 19.0 KB
  产物     : index.html 52.5 KB
  内联脚本 : 2 个
  外链脚本 : 0 个 (单文件自包含)
```

直接用浏览器打开 `web/index.html` 即可本地运行，不需要任何构建工具或依赖。
